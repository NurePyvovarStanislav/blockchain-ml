```powershell
python demo_step3.py

```


## Обрані правила навчального протоколу

1. Поля заголовка: `height`, `timestamp`, `previous_hash`, `merkle_root`, `difficulty`, `nonce`.
2. Вхід SHA-256 заголовка — `canonical_bytes(header.to_dict())` з реалізації Step 1.
3. Листок дерева: `SHA256(0x00 || raw_TXID)`; вузол: `SHA256(0x01 || left || right)`.
4. За непарної кількості вузлів на рівні останній хеш дублюється.
5. Порожнє дерево: `SHA256(0x02)`; це наша домовленість для навчального протоколу.
6. Корінь залежить від **порядку** TXID; жодне автоматичне сортування транзакцій не виконується.
7. Формат дерева **не сумісний з Bitcoin**; це власна реалізація за вимогами методички.

## Чого на цьому кроці немає

- **Proof of Work:** `difficulty=2` у demo — тільки значення в заголовку; nonce ще не підбирається (Step 4).
- **Coinbase:** спеціальну транзакцію винагороди буде додано на Step 4. `BlockTransaction` є мінімальним інтерфейсом, який дасть змогу додати окремий тип coinbase.
- **Генезис / стан / повна валідація історії:** навчальний початковий блок у demo не встановлює правила повноцінного генезис-блока (Step 5).
- **Мережа та розгалуження:** Step 6.

Оскільки дерево дублює останній хеш, деякі різні списки повторюваних TXID можуть давати однаковий корінь, не порушуючи SHA-256. Згодом валідатор має контролювати дублікати TXID і формат блока; для Merkle Proof потрібне також коректне зв'язування форми дерева / довжини списку. Наразі цей модуль дає перевірку **структурної** цілісності, а не всієї криптовалютної транзакції чи мережі.
