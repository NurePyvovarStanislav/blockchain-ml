## Ідея

`LedgerState` зберігає підтверджені баланси та `next_nonce`. `Mempool` виконує чотири перевірки: цифровий підпис, дублікати, nonce, доступний баланс з резервуванням `amount + fee`.

`Mempool.add()` спочатку перевіряє ще раз чинні pending-транзакції відносно актуального стану. `reconcile()` треба викликати після підтвердження блоку чи зміни прийнятого ланцюга.

### Демонстраційне початкове фінансування

Поки немає генезис-блоку, `demo_step2.py` створює `LedgerState({alice.address: 100, ...})` як **довірені тестові дані**. У публічному API не повинно бути операції довільного поповнення балансу. На наступних етапах стан потрібно виводити з перевіреної історії блоків.

`LedgerState.apply_confirmed()` лише імітує застосування підтвердженої транзакції. Вона **не створює блок** й **не здійснює майнінг**. Комісії накопичуються в `unclaimed_fees` до появи логіки винагороди майнера.

### Прийнята політика mempool

- Тільки послідовні nonce (`next_nonce`, `next_nonce+1`, ...), без пропусків;
- Вихідні транзакції резервують `amount + fee`;
- Непідтверджене вхідне надходження не збільшує доступного балансу;
- Усі кошти зберігаються як цілі мінімальні одиниці;
- Після змін підтвердженого стану mempool перевіряється повторно;
- Стан є локальним, потоки, блокування конкурентних запитів і багатовузлова мережа з'являться пізніше.
